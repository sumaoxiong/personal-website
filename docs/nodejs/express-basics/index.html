Express.js 基礎

本章為課程學習後的個人觀念筆記，不包含課程原始圖片、作業與課堂紀錄。

Express.js 是建立在 Node.js HTTP 模組上的 Web framework。它將路由、request body 解析與 middleware 等常見工作整理成較易維護的 API。

建立第一個 Express server​

npm init -y
npm install express
app.js
const express = require('express');

const app = express();
const port = 3010;

app.get('/', (req, res) => {
  res.send('Hello from Express');
});

app.listen(port, () => {
  console.log(`Server running at http://localhost:${port}`);
});
node app.js
curl http://localhost:3010

常用的 app 方法：

方法用途
app.get()、app.post() 等註冊指定 HTTP method 的路由
app.use()掛載 middleware 或 Router
app.listen()啟動 HTTP server 並監聽 port

路由與 HTTP method​

路由由「HTTP method＋URL path」組成。同一個 path 可以根據 method 執行不同操作：

Method常見用途Express
GET查詢資料app.get(path, handler)
POST新增資料app.post(path, handler)
PUT更新整筆資料app.put(path, handler)
PATCH更新部分欄位app.patch(path, handler)
DELETE刪除資料app.delete(path, handler)
app.get('/classes', (req, res) => {
  res.json({ message: '取得課程列表' });
});

app.post('/classes', (req, res) => {
  res.status(201).json({ message: '新增課程' });
});

app.put('/classes/:id', (req, res) => {
  res.json({ message: '更新課程' });
});

app.delete('/classes/:id', (req, res) => {
  res.status(204).end();
});

取得 request 資料​

Express 常用三個位置接收客戶端資料：

來源範例Express 屬性用途
Path parameter/classes/7req.params.id指定某一筆資源
Query string/classes?level=VIP&page=2req.query.level篩選、排序、分頁
JSON body{ "title": "瑜伽" }req.body.title新增或更新的內容

Path parameter：req.params​

在路由中使用 :name 定義動態片段：

app.get('/coaches/:id', (req, res) => {
  const { id } = req.params;
  res.json({ id });
});
curl http://localhost:3010/coaches/7
# {"id":"7"}

Query string：req.query​

app.get('/classes', (req, res) => {
  const { level, page = '1' } = req.query;

  res.json({
    level: level ?? null,
    page: Number(page),
  });
});
curl 'http://localhost:3010/classes?level=VIP&page=2'

req.params 與 req.query 取得的值預設都是字串；當程式需要數字、Boolean 或其他型別時，要進行驗證與轉型。

JSON body：req.body​

Express 不會無條件解析所有 request body。要接收 Content-Type: application/json 的內容，先在路由之前掛載：

app.use(express.json());

接著才能讀取 req.body：

app.post('/classes', (req, res) => {
  const { title, level } = req.body ?? {};

  if (!title || !level) {
    res.status(400).json({ error: 'title 與 level 為必填' });
    return;
  }

  res.status(201).json({ title, level });
});
curl -X POST http://localhost:3010/classes \
  -H 'Content-Type: application/json' \
  -d '{"title":"早晨瑜伽","level":"VIP"}'

express.json() 只處理 JSON，不能用來解析 multipart/form-data 檔案上傳。檔案上傳可使用前一章的 formidable。

Response 與狀態碼​

res.send('hello');                    // 回傳文字或 HTML
res.json({ title: '瑜伽' });         // 回傳 JSON
res.status(201).json({ id: 1 });      // 設定狀態碼後回傳 JSON
res.status(204).end();                // 只結束 response，沒有 body
狀態碼使用時機
200 OK一般成功查詢或更新
201 Created資源建立成功
204 No Content操作成功，不需回傳 body
400 Bad Request欄位缺少、格式錯誤
404 Not Found路由或指定資源不存在
500 Internal Server Error伺服器未預期錯誤

res.send()、res.json() 與 res.end() 都會結束這次 response。送出後不能再修改 status 或 header，也不能回應第二次。

Middleware​

Middleware 是位於 request 與最終 route handler 之間的函式，可以：

  • 執行共用程式，例如 logging 或身分驗證。
  • 讀取或修改 req 與 res。
  • 自己送出 response，結束流程。
  • 呼叫 next()，將處理權交給下一個 middleware。
Request
   ↓
logging middleware
   ↓ next()
JSON / CORS middleware
   ↓ next()
route handler
   ↓
Response

自訂 logging middleware：

app.use((req, res, next) => {
  console.log(req.method, req.url);
  next();
});

Middleware 會依註冊順序執行。如果沒有送出 response，又忘記呼叫 next()，request 就會一直等待。

CORS​

當前端與 API 來自不同 origin（protocol、host 或 port 不同），瀏覽器會套用 Same-Origin Policy。API 可透過 CORS response headers 明確允許指定來源。

npm install cors
const cors = require('cors');

app.use(cors({
  origin: 'http://localhost:5173',
}));

cors() 不是身分驗證或 API 安全機制；它主要是告訴瀏覽器哪些前端來源可以讀取 response。curl、Postman 與伺服器間請求不會像瀏覽器一樣執行 CORS 限制。

使用 express.Router() 拆分路由​

當資源變多時，不應把所有 route handlers 都放在 app.js。可以依資源拆成 Router：

project/
├── app.js
└── routes/
    └── classes.js

Router 檔案​

routes/classes.js
const express = require('express');

const router = express.Router();

const classes = [
  { id: 1, title: '早晨瑜伽', level: 'VIP' },
  { id: 2, title: '重訓入門', level: '一般' },
];

router.get('/', (req, res) => {
  const { level } = req.query;
  const result = level
    ? classes.filter((item) => item.level === level)
    : classes;

  res.json(result);
});

router.get('/:id', (req, res) => {
  const id = Number(req.params.id);
  const targetClass = classes.find((item) => item.id === id);

  if (!targetClass) {
    res.status(404).json({ error: '找不到這堂課' });
    return;
  }

  res.json(targetClass);
});

router.post('/', (req, res) => {
  const { title, level } = req.body ?? {};

  if (!title || !level) {
    res.status(400).json({ error: 'title 與 level 為必填' });
    return;
  }

  const newClass = {
    id: Math.max(0, ...classes.map((item) => item.id)) + 1,
    title,
    level,
  };

  classes.push(newClass);
  res.status(201).json(newClass);
});

router.put('/:id', (req, res) => {
  const id = Number(req.params.id);
  const targetClass = classes.find((item) => item.id === id);

  if (!targetClass) {
    res.status(404).json({ error: '找不到這堂課' });
    return;
  }

  const { title, level } = req.body ?? {};

  if (!title || !level) {
    res.status(400).json({ error: 'title 與 level 為必填' });
    return;
  }

  targetClass.title = title;
  targetClass.level = level;
  res.json(targetClass);
});

router.delete('/:id', (req, res) => {
  const id = Number(req.params.id);
  const index = classes.findIndex((item) => item.id === id);

  if (index === -1) {
    res.status(404).json({ error: '找不到這堂課' });
    return;
  }

  classes.splice(index, 1);
  res.status(204).end();
});

module.exports = router;

在入口掛載 Router​

app.js
const express = require('express');
const cors = require('cors');
const classesRouter = require('./routes/classes');

const app = express();
const port = Number(process.env.PORT ?? 3010);

app.use(cors({ origin: 'http://localhost:5173' }));
app.use(express.json());

app.use('/classes', classesRouter);

app.use((req, res) => {
  res.status(404).json({ error: 'Not Found' });
});

app.use((error, req, res, next) => {
  console.error(error);

  if (res.headersSent) {
    next(error);
    return;
  }

  res.status(500).json({ error: 'Internal Server Error' });
});

app.listen(port, () => {
  console.log(`Server running at http://localhost:${port}`);
});

Router 中的 '/' 會與掛載路徑組合：

app.use('/classes', classesRouter)
                 + router.get('/')
                 = GET /classes

404 與錯誤處理​

Express 依程式碼的先後順序尋找 middleware 與路由，因此掛載順序很重要：

1. 共用 middleware（CORS、JSON parser、logging）
2. Router
3. 404 handler
4. Error handler

404 handler 代表前面沒有任何路由回應，所以要放在所有 Router 後面。

Error-handling middleware 必須有四個參數，即使沒有直接使用 next 也不能省略：

app.use((error, req, res, next) => {
  console.error(error);
  res.status(500).json({ error: 'Internal Server Error' });
});

Express 5 的 async route handler 若拋出錯誤或 Promise rejection，會自動將錯誤傳給 error handler：

app.get('/classes/:id', async (req, res) => {
  const targetClass = await findClassById(req.params.id);

  if (!targetClass) {
    res.status(404).json({ error: '找不到這堂課' });
    return;
  }

  res.json(targetClass);
});

API 測試速查​

# 取得全部課程
curl -i http://localhost:3010/classes

# 使用 query 篩選
curl -i 'http://localhost:3010/classes?level=VIP'

# 取得單筆課程
curl -i http://localhost:3010/classes/1

# 新增課程
curl -i -X POST http://localhost:3010/classes \
  -H 'Content-Type: application/json' \
  -d '{"title":"核心訓練","level":"一般"}'

# 刪除課程
curl -i -X DELETE http://localhost:3010/classes/1

curl -i 會同時顯示 HTTP status 與 response headers，方便確認 API 是否回傳正確狀態碼。
